Every task is a [`just`](https://github.com/casey/just) recipe; `just` lists them. CI runs the same recipes.

```sh
cargo install just cargo-hack cargo-deny cargo-shear cargo-sweep
just servers-setup   # npm packages of the Node test servers, test certificates
just servers         # start them (ports 4200-4206, 4210-4213; no Docker)
just ci              # fmt, cargo-shear + clippy per feature set, tests, docs, cargo-deny, package, plugin
just servers-stop
```

| Recipe | What |
|---|---|
| `just test` | all tests and doctests, then the crate per feature |
| `just test-offline` | codec, backoff and redaction tests that need no server |
| `just plugin` | the Tauri plugin: Rust tests and guest-js (typecheck, vitest, build); needs pnpm |
| `just plugin-example` | builds the example Tauri app |
| `just msrv` | the crate and the plugin on Rust 1.85 with a lockfile resolved for it |
| `just example <name>` | runs an example from `examples/src/bin` |
| `just docs-dev` / `just docs-build` | this documentation site |

## CI

Pull requests run the Linux job. A manual run (Actions → CI → Run workflow) covers Linux, macOS and Windows.

## Documentation site

The site lives in `docs/` (Nuxt, Nuxt Content, Nuxt UI) and is not part of the Cargo workspace or the published packages. Pages are Markdown under `docs/content/`; the changelogs and MSRV page are copied from the repository root by `docs/scripts/sync.mjs`.

```sh
just docs-dev     # http://localhost:3000
just docs-build   # static site in docs/.output/public
```

It is deployed to GitHub Pages by the `docs` workflow, which only runs by hand (Actions → docs → Run workflow).
